Welcome to Bizflow POS

Bizflow POS is a point-of-sale and back-office system made for medical stores and general stores in Pakistan. It sells by tablet, strip or box, keeps every batch with its expiry date, runs customer khata (udhaar), and keeps working when the internet is down. Every screen can be shown in English or Urdu.

This manual explains every screen, every field and every button, in the order you will meet them. Each screenshot comes from the real app. The store in the pictures is a demo store called Bizflow Pharmacy.

Words used in this manual

Main PC
The one computer in each shop that keeps the store’s database. Use your most reliable computer for this.
Extra till
Any other computer in the same shop. It connects to the main PC over the shop network (Wi-Fi or cable).
Store code / Till code
Short codes such as B1 and T01. They are printed in every receipt number, e.g. B1-T01-000013.
Smallest unit
The smallest thing you can sell: a tablet, a capsule, a bottle, a piece. Stock is always counted in this unit. Bigger packs (strip, box) are defined as “holds N smallest units”.
Batch
A lot of stock with its own batch number, expiry date and cost. The till always sells the batch that expires first (FEFO: first-expiry, first-out).
Khata (Udhaar)
A customer’s credit account. Bills put on khata are paid later.
Shift
One cashier’s working time on one till, from opening cash to the closing count and Z-report.
Manager PIN / approval
Some actions (big discounts, refunds above a limit, cancelling a bill…) need another person with approval rights to type their PIN.

Installing and first-time setup

Installing the app on Windows

  1. Copy the installer Bizflow POS_x.y.z_x64-setup.exe to the computer (USB drive, WhatsApp desktop or download).
  2. Double-click it. If Windows shows Windows protected your PC, click More info and then Run anyway. This appears because the installer is not code-signed yet; it is safe to continue.
  3. Follow the installer. When it finishes, open Bizflow POS from the Start menu or the desktop icon.
  4. Repeat on every computer in the shop. Do the main PC first.
Where your data lives On the main PC the store database is the file store.sqlite in C:\Users\<you>\AppData\Roaming\pk.medstore.pos\. Daily copies are kept in the backups folder beside it (see Daily backup files).
Updating to a new version Simply run the new installer over the old one. Your store data is kept. Take a backup first (Store, Users & Settings → Back up now) to be safe.

Checklist before the first sale

  1. Fill in Store details (NTN, drug licence, receipt footer and returns policy).
  2. Add your cashiers in Users & access and give each a PIN.
  3. Load your products: one by one (Add product) or all at once from Excel (Import from Excel).
  4. Connect the receipt printer on each till (Printer setup) and print a test receipt.
  5. Make an owner recovery code and keep it somewhere safe.

Finding and adding items

  • Scan the barcode with the scanner. The item is added at once, in the pack the barcode belongs to (e.g. a box barcode adds one box).
  • Type part of the brand name, the formula (e.g. paracetamol) or the company. Every word must match, so pan 500 finds Panadol 500mg.
  • Press Enter to add the first result, use ↑ ↓ to pick another one, or click it.
  • Each result shows the stock on hand and the price of each pack.
  • F2 jumps back to the search box from anywhere; Esc clears the search.

Manager approval

When a cashier does something the store rules don’t allow alone, a box asks for approval. Nothing is saved until someone approves.

  1. The box says why approval is needed (e.g. A discount above 5% needs a manager PIN).
  2. The approver taps their name under Who is approving?. Only the owner and cashiers marked Can approve are listed.
  3. They type their PIN (or the owner types the password) and press Approve.

Every approval is written in the activity log with both names. Several wrong PINs lock that approver for a while.

The owner sets which actions need approval in Needs a manager PIN.

Parts of the receipt

  1. Header — store name, address, phone, NTN and drug licence (from Store details).
  2. Bill details — receipt number, date and time, cashier and till, customer.
  3. Lines — product, quantity × price, batch number (B:) and amount. Weight items show grams and price per kg.
  4. Totals — items, subtotal, discount, total, how it was paid and the change.
  5. Returns policy — your own text, set in Store details. Leave it empty to print none.
  6. Footer — your thank-you message.
  7. Barcode — the receipt number as a barcode. Scan it on the returns screen to find the bill instantly.

Khata sales also print the customer’s balance. When FBR reporting is on, the FBR invoice number and QR code are printed too.

A customer whose khata profile says Urdu receipt gets an Urdu receipt; everyone else gets the store’s default receipt language.

Selling on khata (udhaar)

  1. Choose the customer in Customer. Their current balance is shown next to the name.
  2. Choose Khata (Udhaar) as the payment method. The note under it confirms the bill will be added to their udhaar.
  3. Press Pay & print receipt. If the bill would take them over their credit limit, a manager PIN is needed.

The bill appears at once in the customer’s ledger under Customers & Khata.

Returns and refunds

Press F9 or Return / Refund.

  1. Scan the barcode printed on the customer’s receipt, or type the receipt number, then Find. Offline receipts (X numbers) can be found the same way once they are synced.
  2. The bill shows what was sold, what has already been returned and the batch of each line.
  3. For each item coming back, set the Return quantity with − +. You can return part of a strip if it was sold by tablet.
  4. Choose the Reason: Not needed any more, Wrong item given, Doctor changed medicine, Damaged pack.
  5. Choose the Condition:
    • Sealed — back to stock: goes back on the shelf under its original batch and expiry.
    • Damaged — write off: not added back; recorded as a loss.
    • Expired — return to supplier: kept aside for the supplier, not sellable.
  6. Choose Give refund as: cash, card, JazzCash, Easypaisa, or Khata credit (takes it off the customer’s udhaar). Khata bills can only be refunded to khata.
  7. Press Refund & print slip.
Rules for returns Fridge items are marked not returnable and can’t be returned. Refunds above the store limit (Rs 500 by default) need a manager PIN; several small refunds on the same bill are added together for this check. A cash refund can never be more than the cash in the drawer.

Selling when the main PC is unreachable

If the network or the main PC goes down, an extra till keeps selling from its own copy of the product list. A yellow badge shows Main PC not reachable — selling from this till’s copy.

  • Receipts get their own number series with an X, e.g. B1-T02-X000001.
  • Payment by cash, card, JazzCash or Easypaisa. Khata, returns and cash moves wait until the main PC is back.
  • Prices come from the copy the till downloaded last. The main PC checks every offline sale against that price list when it arrives.
  • When the main PC answers again, the waiting sales are sent automatically and the badge turns green. Stock is taken off then.
  • If the main PC refuses a sale (for example a price that was never on the list), it is kept and shown to the owner, so nothing is lost.
Important Don’t close or reinstall an extra till while it still has offline sales waiting. The till warns you if it cannot store them safely.

Stock count

Count one shelf at a time while the shop keeps selling.

What to countWhole shop, one rack (e.g. Rack A1 · 5 batches) or Items with no rack.

Owner recovery code

If the owner password is forgotten, this code sets a new one on the main PC. Press Make a new recovery code, write it down or print it, and keep it somewhere safe outside the shop. The code is shown only once. It works once; make a new one after using it. Making a new code stops any older code from working.

Cloud backup

Each store gets its own free Turso database. With cloud backup on, every sale and change is copied to the cloud within moments, so a broken or stolen PC loses nothing, and the owner can see all branches in All stores.

  1. Create a free account at turso.tech. Create a database for this store (e.g. store-b1).
  2. Copy its Database URL (starts with libsql://) and create a token.
  3. Paste both here and press Turn on cloud backup.

The status in the bottom-left of the Backoffice shows Cloud backed up · 12:41, Offline · N changes waiting (no internet; it catches up automatically) or Cloud backup off. While off, nothing leaves this PC. Private settings such as the FBR token are never sent to the cloud.

Daily backup files

A copy of the store database is made on the main PC once a day; the last 14 are kept in the folder shown. Back up now makes one immediately. Copy one to a USB drive now and then, and always before reinstalling Windows.

Paid add-ons

SMS OTP for password reset and automatic WhatsApp messages need a paid SMS/WhatsApp provider and are off. While off, the free option is used: the owner recovery code, and the WhatsApp button that opens WhatsApp with the message typed for you.

Daily routines

Opening the shop

  1. Switch on the main PC first, then the extra tills.
  2. Each cashier signs in and enters the opening cash.
  3. Check the connection badge is green on every till.
  4. Owner: glance at Dashboard → Expiring within 90 days and move those items to the front.

During the day

  1. Receive every delivery as a GRN with batch and expiry.
  2. Record shop costs in Expenses or as Cash out.
  3. Put khata payments in Receive payment.
  4. Check Low stock before calling the distributor.

Closing the shop

  1. Each cashier closes their shift, counts notes and prints the Z-report.
  2. Owner: open Activity log → Needs attention.
  3. Check the cloud status says Cloud backed up.
  4. Shut down extra tills first, the main PC last.

Weekly / monthly

  1. Count one or two racks each week with Stock count.
  2. Run the Expiry report and return expiring stock to suppliers.
  3. Send WhatsApp reminders to overdue khata customers.
  4. Pay suppliers from Supplier payables.
  5. Copy a daily backup file to USB.

Troubleshooting & questions

An extra till says “Can’t reach the main PC”.
Check the main PC is on and Bizflow POS is open on it, and that both are on the same Wi-Fi/network. If the main PC’s address changed, use Change this computer’s setup and type the new address. Give the main PC a fixed IP in your router so this doesn’t happen again. Meanwhile the extra till can keep selling offline.
The receipt doesn’t print.
Owner: open Printer on that till, choose the right printer and paper width, and press Print test receipt. Make sure the printer is switched on, has paper and is installed in Windows.
The scanner adds nothing.
Click in the search box (or press F2) and scan again. If the item is not found, the barcode is not saved on any product: add it in Edit product → Barcodes.
A cashier forgot their PIN.
Owner: Store, Users & Settings → Users → Edit, type a new PIN and save.
The owner forgot the password.
On the main PC tap Forgot password? and type the recovery code. Without a recovery code, contact your Bizflow support person.
Stock on screen doesn’t match the shelf.
Look at Stock changes on the product to see what happened, then fix it with Correct or a stock count. Check that deliveries were received as GRNs and returns were done on the returns screen.
Cash is short at closing.
Recount once. Check the Z-report’s cash out and refunds lines and the activity log for that shift. Write the reason in the note.
Windows says the installer is unsafe.
Click More info → Run anyway. The installer is not code-signed yet.
We are moving the main PC to a new computer.
With cloud backup: install on the new PC, choose This is the main PC, then Restore from cloud backup. Without it: copy the latest daily backup file to the new PC and ask your support person to restore it.
